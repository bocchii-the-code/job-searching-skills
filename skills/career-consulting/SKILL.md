# Career Consulting

给用户做求职与职业路线咨询。技能本身不含任何个人档案——档案来自工作区里的 `Profile.md`（首次运行时访谈生成）。产出文档语言以 Profile 偏好为准（默认中文）。

## 0. 定位工作区与 Profile

- 工作区优先用 Profile 里记录的路径；没有就问用户把求职文档放在哪个目录（默认建议当前项目根目录）。
- 读工作区根目录的 `Profile.md`：
  - **不存在**：按下面模板访谈生成——一次问 10–15 个问题，回显给用户确认后写入。
  - **已存在**：只问本期变化项（毕业/入职状态、签证、目标城市、约束、进行中的申请），确认后更新「最后更新日期」。

```markdown
# Profile
- 国籍与签证状态：
- 学历与毕业时间：
- 目标岗位族：
- 目标城市/国家（含排除项）：
- 当前阶段：
- 求职约束：
- 长期目标：
- 输出语言偏好：
- 工作区与文档索引（逐条列：文件名 —— 用途）：
- 最后更新日期：
```

## 1. 时效扫描 → 报待办 → 问意图

每次运行开头先扫一遍工作区活文档：

- 30 天内的截止日：提到简报最前面；
- 岗位/批次状态超过 30 天未核实：标「待复核」，引用前重查；
- 薪资/招聘窗口数据超过 180 天：引用前重查；
- 打不开的岗位页：先按 `references/link-verification.md` 用真实浏览器/官方接口复核再下结论（静态抓取失败 ≠ 页面失效）；确认失效的从工作手册删除，需要留痕的记入档案文件「已关闭」一行，并在文档头更新行记一句删了什么。

然后读 Profile 与活文档，给一段短简报：进行中的申请、最近截止日、待复核项、上次遗留的下一步。最后让用户选这次做什么：

调研新公司 / 市场扫描 / 投递决策 / offer 对比 / 签证与身份 / 长期路线 / 更新文档。

## 2. 按分支执行

- **调研新公司 / 市场扫描** → 读 `references/research-and-docs.md`，按其执行（一律深挖：按公司集群分组调研——有并行代理则并行、否则串行；一手来源优先）。
- **匹配度、实习 vs 直投、offer 取舍、行动清单** → 读 `references/decision-framework.md`。
- **签证、身份、城市/国家选择** → 读 `references/visa-guide.md`，对标注「须重查」的字段先核实。
- **简历定位与关键词**：只给建议；简历文件的修改交给专门的简历技能（如 resume-refiner、rendercv，若环境中已安装）或用户自行处理。

## 3. 更新活文档

按 `references/research-and-docs.md` 的模板与来源规范更新工作区文档（完整 https 链接、来源带日期）；失效条目已在步骤 1 的扫描中清理。信息若触及 Profile 字段，顺手更新 Profile。

## 4. 交付

每次运行结尾给出四件套：**匹配度评级** + **实习/直投建议** + **关键截止日** + **下一步动作清单**（谁、在什么时候、做什么）。
