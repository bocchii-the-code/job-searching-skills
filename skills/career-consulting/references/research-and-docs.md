# 调研与文档规范

调研分支的执行手册：怎么调、信什么、写进哪、怎么维护。

## 调研方式

一律深挖。把目标公司按集群分组（每路 3–5 家）：有并行后台代理能力时每路派一个并行执行；没有时按同样分组串行推进。主会话负责整合与落笔（单一写者，避免并发改文件）。

每路调研的 prompt 要自包含：候选人画像、公司清单、要回答的问题、输出格式、来源要求。输出须包含：

- 状态：批次是否开放、窗口、截止日、地点、投递名额
- 渠道：官方入口与流程要点（笔试/面试轮次）
- 最匹配岗位表：岗位 / 地点 / 类型 / 匹配原因 / 完整链接
- 实习还是直投建议
- 薪资（标注口径）
- 来源：逐条带日期

## 来源分级

- **一手**：公司官网、官方招聘系统（飞书/Moka/Beisen 等）、官方公告与公众号、政府移民局页面。
- **二手**：牛客、职友集、看准、猎聘、offer 汇总、新闻媒体——引用时标「二手」。
- **未证实**：无法用一手来源确认的，标「未证实」，并写清待核实的点。
- 每条关键事实带来源与日期；链接一律写完整 `https://` 地址。
- 招聘门户多为 JS 渲染：静态抓不到就说明，改用官方 API、官方公告与真实分享链接交叉验证。

## 公司章节模板

每家公司按固定结构成节（所有公司一致）：

### 公司名 — 匹配度：高/中/低（一句话理由）

**状态（调研日期）：** 批次、窗口、截止、地点、投递名额
**渠道：** 官方入口与流程要点
**最匹配岗位：** 表格：岗位 / 地点 / 类型 / 匹配原因 / 链接
**实习还是直投：** 结论 + 理由
**薪资（标注口径）：** 数字 + 来源
**来源：** 逐条（来源 + 日期）

## 文档更新规范

- **活文档优先**：默认更新工作区现有文档（市场主文档、薪资文档等），不每次另起快照。
- 文档头保留：调研日期、最近更新日期、候选人一行画像、一句话结论。
- 文末保留：来源登记（一手/二手分组）、未证实清单。
- **失效页面清理**：由每次运行开头的时效扫描执行（见 `SKILL.md` 步骤 1）——打不开的条目直接删除，不设历史区。核查方法见 `references/link-verification.md`。
- 新增公司/市场照模板成节；同一信息只保留一处（正文一处真相，来源进登记表）。

### 两文件结构（2026-10 起实践；示例：`JOB.md` + `JOB_archive.md`，其他工作区按同构方式命名）

- **工作手册**＝日常行动用：顶部「行动区」（按日期排序的截止表＋「无截止日但优先」清单，每次运行先刷新）→ 当前职位列表（逐行：公司/职位｜地点·类型｜核验状态｜链接，只列可申请职位）→ 行动计划与规则。参考类内容（公司背景、薪资明细、来源）不放这里。
- **档案文件**＝参考用：公司档案（现状一句＋可投链接＋薪资一行＋避坑＋已关闭一行）、届别与窗口表、已截止总表、完整来源登记。
- **逐行时效标注**：每行标核验方式与日期（如「确认在招（10-11）」「9-16 快照」）；「快照」= 当日核验、之后未复核，超过 30 天按 `SKILL.md` 步骤 1 重查。
- **链接维护**：链接一律可点击 markdown 格式；整理、重组、批量改动前先刷新 `.bak`，改后用「URL 清单对比」校验无意外丢失（见 `references/link-verification.md` 第 4 节）。
- 已关闭条目在工作手册不留历史区；需要留痕时写入档案的「已关闭」一行或已截止总表。
